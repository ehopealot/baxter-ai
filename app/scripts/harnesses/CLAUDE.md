# The harness layer

(part of Baxter — see [architecture map](../../CLAUDE.md))

This is the harness-agnostic run driver and the harness adapters that `runtime.ts`'s `runAgent` selects. It was extracted from the `discord-bot.ts` narrative; the pure Discord-gateway behavior (response gate, reaction wake, dispatchers) lives in [discord.md](../../docs/architecture/discord.md).

`runAgent` is the harness-agnostic driver; the Claude Code specifics (invocation, stream-json decoding, rate-limit detection) live in `scripts/harnesses/claude.ts`, selected via `BAXTER_HARNESS` (**default `openrouter`** — the safe, cwd-confined posture; `claude` is explicit opt-in because its native `Read` isn't cwd-bounded, see [Auth](../../docs/architecture/security.md); an unknown value fails at daemon startup). The two Claude-Code-isms it deliberately leaves caller-side — `allowedTools` (the enforced tool-permission boundary) and `.claude/skills` staging — are documented at the top of that adapter. **Three more harnesses** drive Baxter through a **structured-tool** layer instead of Claude Code (no shell: `run_cli` reinterprets `allowedTools`' `Bash(...)` patterns as an execFile allowlist, and read/write/edit are cwd-confined, writes also refusing `.claude/`; the executors live in `harnesses/openrouter-tools.ts`, the shared preamble + tool set in `harnesses/runner-common.ts`, and the runner→adapter event decoding in `harnesses/runner-events.ts`): **`openrouter`** (`openrouter.ts` + `openrouter-runner.ts`) via OpenRouter's Agent SDK (`@openrouter/agent`), needs `OPENROUTER_API_KEY`/`OPENROUTER_MODEL`; **`openai`** (formerly `local` — kept as a back-compat alias; files stay `local.ts` + `local-runner.ts`) driving any OpenAI **chat/completions** endpoint (self-hosted via Ollama/LM Studio, default `http://localhost:11434/v1`, or a REMOTE one like OpenAI), needs `OPENAI_MODEL` (+ optional `OPENAI_BASE_URL`; a remote endpoint needs `OPENAI_API_KEY`); and **`custom`** (`custom.ts` + `custom-runner.ts`) driving any keyed LLM API whose **native** wire format ISN'T OpenAI chat/completions, via a pluggable **dialect** (`harnesses/dialects/<name>.ts` — 4 pure, unit-tested functions: `buildRequest`/`parseResponse`/`classifyError` + `defaultBaseUrl`) selected by `CUSTOM_API_DIALECT` (`anthropic|gemini`); ships `anthropic` (Claude Messages API — real Claude by key, no Claude Code binary) + `gemini` (Google generateContent), needs `CUSTOM_API_DIALECT`/`CUSTOM_API_MODEL`/`CUSTOM_API_KEY` (+ optional `CUSTOM_API_BASE_URL` to target a proxy). Unlike local's in-place OpenAI-array loop, `custom-runner` keeps a dialect-**neutral** normalized transcript the dialect renders to wire per call (so `fitContext`'s analog is `fitTranscript`, preserving only item 0); its wrap-up turn **suppresses** tool use (`tool_choice:none` / Gemini `toolConfig` NONE) rather than omitting the tools param, since both APIs reject a request whose transcript carries tool_use/tool_result blocks with the tools dropped. `CUSTOM_API_KEY` rides the exact posture of `OPENROUTER/OPENAI_API_KEY` (kept in the runner env, unreadable by the run on the structured-tool harness). Together `local` + `custom`'s dialects cover essentially every hosted LLM API (most third parties also expose OpenAI-compat). See `docs/superpowers/specs/2026-07-23-custom-api-harness-design.md`. All experimental; the model must support tool calling. **Context-blowout guards** (these hand-rolled loops don't self-compact the way `claude -p` does): every tool result is size-capped — CLI output at `*_CLI_OUTPUT_MAX_BYTES`, and native `read`/`load_skill` too (previously the one uncapped path, `capRead` in `openrouter-tools.ts`); the **local** runner also holds the whole message array under `OPENAI_CONTEXT_MAX_TOKENS` by stubbing the oldest tool results (then oversized tool-call arguments, e.g. a big `write_file`) in place before each call (`fitContext` in `runner-common.ts` — keeps the system + original prompt and the tool_call/tool_result pairing intact, trims-and-continues); the **openrouter** runner can't trim mid-loop (the SDK owns the array) so it instead *stops* early via the SDK's `maxTokensUsed(OPENROUTER_MAX_TOKENS)` stop condition + `allowFinalResponse`. **If the window is exceeded anyway**, both runners recover rather than hard-fail: a context-full error is detected (`isContextFullError`) and the run trims + retries — the local runner halves its own array and retries (`OPENAI_CONTEXT_RETRY_MAX`); the openrouter runner truncates the oldest tool OUTPUTS in the SDK's saved `ConversationState` (`trimStateToolOutputs`) and resumes `callModel` (`OPENROUTER_CONTEXT_RETRY_MAX`) — this resume-after-overflow path is **verified live against minimax's 204k window**. **Last resort — model escalation:** any request failure that ISN'T out-of-credits/rate-limit — crucially INCLUDING minimax's opaque `invalid_prompt`/"invalid request" for an over-long request, which `isContextFullError` can't recognize (that miss once turned a ~1 MB scoreboard payload into a hard fail with the reply dropped) — triggers a one-shot resume on a larger-context fallback model (`shouldEscalateModel`; `OPENROUTER_FALLBACK_MODEL`, default the already-configured `OPENROUTER_MULTIMODAL_MODEL` — historically minimax-m3, whose ~1M window vs m2.7's ~205k motivated the escalation). So a big tool payload becomes survivable (the bigger window swallows it, nothing trimmed) instead of a dropped reply; escalation is one-shot, skipped when already on the fallback, and reuses the saved `ConversationState` (or re-sends the original task if the SDK failed before saving). A shared `tryEscalate` closure applies it in BOTH the main tool loop AND the give-up **nudge/poke** resume, because an overflow can first surface at the nudge — the main loop fitting under the window but the poke's added turn tipping past it silently dropped an owed reply (2026-07-20) until the nudge path shared the escalation. Complements keeping responses small at the source (scoped queries). If trimming AND escalation still can't fit it, a **recognized** context-full error ends the run *gracefully* (exit 0, a clear "context full" result) so heartbeat doesn't retry into the same wall and discord/poll don't count it a hard failure; the opaque `invalid_prompt` shape (unrecognized by `isContextFullError`) still **hard-fails** (exit 1) when escalation is spent/disabled — a fresh heartbeat retry escalates again. See `docs/superpowers/specs/2026-07-17-openrouter-harness-design.md`.

**Multimodal routing (openrouter harness):** when `OPENROUTER_MULTIMODAL_MODEL` is set and an INBOUND trigger carries media (image/video/audio/PDF), that one run is routed to that model (e.g. `google/gemini-2.5-flash`) with the attachment(s) attached to the first turn. The **same knob covers all three inbound surfaces** (Discord, mail, SMS); each daemon passes the routing to the run through the identical env vars (`BAXTER_MODEL_OVERRIDE` + `BAXTER_MEDIA`), and the runner turns `BAXTER_MEDIA` into the SDK's `input_image`/`input_video`/`input_file`/`input_audio` content parts (`buildMediaParts`, camelCase — `callModel` serializes through the outbound schema). Empty knob or a media-less trigger → the default text model, unchanged. (This is inbound-only — Baxter doesn't send media out on any surface.)

`buildMediaParts` gates each item on scheme only (`isModelFetchableUrl`: an https string), NOT on a per-provider host allowlist. `BAXTER_MEDIA` is written only by a daemon (it lives in the runner env, never the run env, so the model run can't set it), and each daemon host-validates its OWN source at selection time — so the runner needs no host list, and adding a surface never means editing a host set in the runner. image/video/PDF are **URL-passthrough** (OpenRouter fetches the url); audio has no url field in the API, so it's fetched + base64'd (size-capped, `MEDIA_AUDIO_MAX_BYTES`).

- **Discord:** the daemon detects media at notify-time (`selectMediaAttachments`, host-validated to the Discord CDN + type/count capped), carries it across the debounce coalesce (`_coalesce` unions prev+next media oldest-first so "image then caption" keeps the image). Every attachment is also surfaced in the transcript as a short sanitized marker (`[image: cat.png]`, via `attachmentMarkers` in `renderHistory`).
- **Email:** a Resend attachment has **no public url** on the listing (just an `id` + metadata), so `mail-bot`'s `selectMailMedia` filters the inbound's attachments to the forwardable types (image/video/audio/PDF), caps at `MAIL_MEDIA_MAX`, and — only when routing, lazily in the dispatcher's `runFn` — mints each one's short-lived signed download url via `mintAttachmentDownload` (the credential-holding step; the api key mints the url, the url is then fetched without it). Those urls ride `BAXTER_MEDIA` as `source:"resend"` items (a url + metadata, never bytes), so `buildMediaParts` URL-passes them exactly like Discord's. Best-effort: a mint failure or non-https url drops just that item. `buildPrompt`'s `get-attachment` line stays as the model's fallback for anything not forwarded (e.g. an over-cap or non-forwardable attachment).
- **SMS:** Sendblue's inbound webhook carries a public signed `media_url` but no content-type, so `sms-bot`'s `smsMedia` infers one from the url extension (image-dominant → unknown defaults to image/jpeg) and passes the single url as a `source:"sendblue"` `BAXTER_MEDIA` item — the lightest path, a pure URL-passthrough with no mint. Only the triggering message's media is attached natively; prior messages keep the `[image]` transcript marker (`renderHistory`) since history isn't re-fetched.

See `docs/superpowers/specs/2026-07-18-discord-multimodal-m3-design.md` and `docs/superpowers/specs/2026-07-31-email-multimodal-design.md`.

**Usage metering:** every runner reports a `usage` object (real USD `cost` + tokens + effective `model` + `src`) on its terminal `result` event — openrouter sums per-turn `usage.cost` across the whole run via `getFullResponsesStream` (`openrouter-usage.ts`), claude reads `total_cost_usd`/cache-aware tokens off the stream-json result line, openai/custom report tokens with `cost:null`. `runAgent` records it to the per-tenant ledger and runs the fail-open soft budget cap. See [usage-metering](../../docs/architecture/usage-metering.md).
