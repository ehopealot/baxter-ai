# The mail agent

(part of Baxter — see [architecture map](../../CLAUDE.md))

A daemon (`scripts/poll.ts`) polls a dedicated AgentMail inbox every `POLL_INTERVAL_SECONDS`. For each new, allowlisted, non-automated thread, it spawns one scoped `claude -p` run (the persona "Baxter") with a rendered prompt containing the full thread transcript. That run can reply in-thread, research the web via `WebSearch`/`WebFetch` and browse/interact via the Playwright CLI skill (persistent browser profile → logins/cookies carry over between emails), and read/write a small cross-thread memory file. Configured via `app/.env` (copy from `app/.env.example` — every var is commented there).

Run it via the root `Makefile`: `make run` starts the **default fleet** (Discord gateway + heartbeat + codapi) detached, docker-compose-managed (`compose.yaml`). **The mail poller (`poll.ts`) is opt-in** — `make run-mail` adds it (gated behind compose's `mail` profile; opt-in only because Discord is the default surface, not for any maintenance reason — AgentMail is a single API key). `make mail`/`make discord` run a single surface in the foreground, `make stop` tears the fleet down, `make inbox` (one-time AgentMail inbox provisioning), `make app-shell` (debug shell). See root `CLAUDE.md` for the compose model (images built by the Makefile; network + config volume are `external`).

## File map (mail surface)

- **`scripts/poll.ts`** — the daemon loop. Groups new messages by thread, dispatches at most one `claude -p` run per thread per cycle, enforces `MAX_EMAILS_PER_CYCLE`/`MAX_SENDS_PER_DAY`, and writes the 0600 AgentMail API key file at startup (see [Auth](security.md)).
- **`scripts/mail.ts`** — the credential boundary for the mail surface (reads the AgentMail API key env-first-then-file). CLI wrapper around the AgentMail API via the `agentmail` SDK (`list-new`, `get-thread`, `reply`, `send`, `label`), invoked as a subprocess by both `poll.ts` and the spawned `claude -p` run's `Bash` tool. `list-new` pages the inbox from a persisted timestamp cursor (`MAIL_POLL_CURSOR_PATH`, held one margin below the oldest unhandled message) and excludes the `agent-processed` label (the exactly-once source of truth) plus own mail; every `reply`/`send` applies a `baxter-sent` label so the agent's own messages are self-identifiable. The pure cores (`classifyListing`/`buildThreadOutput`/…) are unit-tested with an injected fake client, and the SDK is imported lazily so the tests need no network. The CLI-dispatch block is guarded with an `import.meta.url`/`pathToFileURL` check so importing the pure exports doesn't trigger dispatch.
- **`scripts/send-state.ts`** — the daily send-cap counter (`MAX_SENDS_PER_DAY`), incremented by `mail.ts` at the actual send call (not by `poll.ts` at dispatch time — a run can send more than one email).
- **`scripts/make-inbox.ts`** — one-time AgentMail inbox provisioning (`make inbox`): create-or-show Baxter's inbox and print `AGENTMAIL_INBOX_ID`/`BAXTER_EMAIL` for `app/.env`.
- **`prompt.md`** — the template rendered per thread. Uses `{{FROM}}`/`{{SUBJECT}}`/`{{BODY}}`/`{{MESSAGE_ID}}`/`{{MEMORY_PATH}}`/`{{CREDENTIALS_PATH}}`/`{{MAIL_CLI_PATH}}`/`{{PERSONA_NAME}}`/`{{BAXTER_EMAIL}}`/`{{PROJECTS_LIST}}`/`{{LEARNED_SKILLS_LIST}}`/`{{LOADED_SKILLS}}` placeholders.
- **`tui-prompt.md`** — the chat template for the interactive terminal (see [Interactive terminal / TUI](tui.md)). Placeholders `{{PERSONA_NAME}}`/`{{MESSAGE}}`/`{{MEMORY_PATH}}`/`{{CREDENTIALS_PATH}}`/`{{LEARNED_SKILLS_DIR}}`/`{{PROJECTS_LIST}}`/`{{LOADED_SKILLS}}`/`{{LEARNED_SKILLS_LIST}}`.
