# Interactive terminal / TUI (`baxter shell` → `scripts/tui.ts`)

(part of Baxter — see [architecture map](../../CLAUDE.md))

The operator's own console — **not** a fleet daemon; run on demand. A plain line **chats** with Baxter (a **fresh run per turn** — no history threading yet, so continuity is via `MEMORY_DIR`); a **`/slash`** line runs one of his tools directly, or a meta command (`/help`/`/tools`/`/memory`/`/skill [name]`/`/harness`/`/clear`/`/exit`). A **bare list-type verb** (`/projects`/`/schedule`/`/files`/`/data`/`/mail`/`/discord`) runs its CLI's static list subcommand (`SLASH_TOOL_DEFAULT` in tui-core; args suppress it — note `/mail`→`list-new` advances the shared poll cursor); a bare `/skill` lists baked + learned skills, and `/skill <name>` opens one (re-staging first, so it live-reloads an in-session edit; `/load_skill`/`/loadskill` alias to it). Two deliberate **trust tiers**: a **chat** goes through `runAgent` (so `stripRunSecrets` applies — the LLM never sees the keys) with the generous `TUI_TOOLS` allowlist (mail + discord + schedule + core); a **`/slash` passthrough** runs a CLI *as the operator*, in the TUI's own keyed env — the same as typing it in `app-shell`. **The security boundary is `tui-core.resolveSlash`** (unit-tested): a verb resolves to an **argv array** only for the static `SLASH_TOOLS` allowlist (`hasOwnProperty`, not `in`), **never a shell string**, so metacharacters in args are inert and an unknown verb errors. `/code <lang>` is the one multi-line verb (body collected to a lone `.`, piped to `code-cli` stdin).

It's a **fifth `runAgent` caller**: it stages skills (`TUI_SKILL_SRCS`), shares `MEMORY_DIR` (talks to the *real* Baxter — concurrent writes with the fleet are the accepted `Edit`-over-`Write` case), and **writes the 0600 key files at startup** (`AGENTMAIL_KEY_PATH`/`DISCORD_TOKEN_PATH`, like `heartbeat.ts`) so standalone chat runs' mail/discord calls still auth. It also sets **`BAXTER_TERMINAL=1`** in the run env: the reply-channel rule is surface-dependent, so `systemPreamble(cliMap, {terminal})` (via `isTerminalRun()` in each structured runner) tells the run its reply is its **final message TEXT**, not a `discord-cli`/`mail` tool call — without it the shared "a reply IS a tool call" rule (correct for Discord/mail, which have no other channel) made a TUI run **post its answer to Discord**. Those tools stay granted for when the operator explicitly asks to reach a channel/person. Live rendering taps the **harness-agnostic** seam: `runAgent`'s new `onEvent(ev)` hook (inside `emit()`'s `adapter.parseEvents` loop) feeds the TUI **normalized** events, so it renders under `claude` too (not just openrouter/local). Pure logic (parse/allowlist/render/key-file/body) lives in **`scripts/tui-core.ts`** (`tui-core.test.ts`); `tui.ts` is the thin readline shell; `tui-prompt.md` is the chat template. **`make tui`** docker-runs it locally with `APP_RUN_FLAGS` (the `--network` matters — `/code` needs codapi); `baxter shell` actually calls **`make tui-run`** — the same `docker run` but WITHOUT the per-launch `build-app` rebuild (the image is built at install / `baxter build` / `baxter update`; `tui-run` builds only if it's missing), so startup is fast. `baxter shell <box>` / `BOX=<box>` runs the identical terminal on that box over SSH. Design: `docs/superpowers/specs/2026-07-23-baxter-tui-design.md`.
